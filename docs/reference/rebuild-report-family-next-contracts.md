## Source defects and disconnected controls

1. **RPT-11 wrong date property:** `TopPaymentDate.tsx:63` declares accessor `payment_date` but its cell destructures `paymentDate`. API rows come from PaymentDates with `payment_date`. The source `dayjs(undefined)` can display today's date instead of the promise date. Current must render actual `due`; never duplicate that bug. Its “View Products” button at 95 has no handler and no promise meaning; do not add a dead product link.
2. **Misleading sums:** RPT-05 `app.py:4319` sums `row['clint']['amount']` for every note; RPT-10 `5469` does the same for every promise. These multiply original debt by activity count. Current note/distinct-case counts and exact promise-status amount totals are correct; do not invent a recovery total or sum repeated debt.
3. **Latest status semantics:** RPT-09/10 source finds latest comment by creation timestamp (`5335` onward, `5427` onward), then looks up its status. Null/unclassified latest comments can break `comment_status.as_dict()`; duplicate latest queries also occur. Current promises select latest effective non-retired **classified** note, falling back past plain notes, with deterministic source/ID ties. That is an intentional current contract, not exact equivalence to all latest source notes. A column reorder must preserve it and label it accurately.
4. **Commented-out receipt columns:** Both note/promise table files contain long `/* ... */` blocks of payment/approval fields after their active definitions. Search hits inside these blocks are not missing visible note/promise columns. Promise files also comment out note-text and duplicate status columns between active columns; they are not part of the ten-column list.
5. **General endpoint scope:** Source general note/promise endpoints do not provide the current guarded scope contract. Current read/export intersection, fresh generation authorization and retained provenance/download checks must remain.
6. Generic backend `filter_mui` and typed `FilterServerSide` are different paths. Typed amount ranges are integer-parsed in old source; exact decimal/one-sided current RPT-09/10 amount bounds deliberately improve them. Do not infer RPT-11 amount or generic UI controls from another report's panel. Source `UserTableSearch` controls are commented out in the report tools; API operators alone do not prove an active user-facing menu.
